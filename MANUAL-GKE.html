Self-contained doc to bring the cluster back up months from now without remembering anything. Assumes an empty GCP project (no repo, no images, nothing) and ends with a GKE cluster running the 6 microservices and validated externally with Bruno.

Up-to-date The EazyBank Section 17 repo must be cloned locally at C:\Users\User\spring boot\section_17. All commands run from there in PowerShell.
Current cost Everything deleted on 2026-08-07. State: $0/month. See §12 for the breakdown on recreation.

0Machine prereqs

  • Google Cloud SDK (gcloud + gke-gcloud-auth-plugin). Windows: official installer.
  • kubectl — gcloud components install kubectl or the one that ships with Docker Desktop.
  • helm v3+.
  • Docker Desktop — needed for the image build+push in §4.
  • JDK 17+ — for the Jib build.
Warning If kubectl complains about gke-gcloud-auth-plugin not found, the plugin is not on PATH. Add it to the session with: 
$env:PATH += ";C:\Users\User\AppData\Local\Google\Cloud SDK\google-cloud-sdk\bin"
or open a new PowerShell.

1Log in to GCP and configure the project

gcloud auth login
gcloud config set project project-aaa96c1a-20d1-43bf-819
gcloud config set compute/region us-central1
gcloud config set compute/zone us-central1-a

gcloud auth login opens the browser for OAuth. Once per machine/account.

2Enable APIs persists

Enable three APIs. If they are already enabled, this command is idempotent and does not cost anything.

gcloud services enable container.googleapis.com artifactregistry.googleapis.com compute.googleapis.com

Check:

gcloud services list --enabled --filter="name:(container.googleapis.com OR artifactregistry.googleapis.com OR compute.googleapis.com)" --format="value(config.name)"

3Create the Artifact Registry repo deleted 2026-08-07

gcloud artifacts repositories create eazybank `
  --repository-format=docker --location=us-central1 `
  --description="EazyBank microservices Docker images"

The repo costs ~$0.06/month for the images it will hold (~630 MB). See §12.

4Local build + push to Artifact Registry

Configure Docker to auth against AR (once per machine):

gcloud auth configure-docker us-central1-docker.pkg.dev

Build the 6 images with Jib (produces eazybytes/<svc>:s17 tags):

cd "C:\Users\User\spring boot\section_17"
.\build-images-s17.ps1

Retag and push:

$svcs = @("configserver","accounts","cards","loans","gatewayserver","message")
foreach ($s in $svcs) {
    $dst = "us-central1-docker.pkg.dev/project-aaa96c1a-20d1-43bf-819/eazybank/${s}:s17"
    docker tag "eazybytes/${s}:s17" $dst
    docker push $dst
}

Check that all 6 are there:

gcloud artifacts docker images list us-central1-docker.pkg.dev/project-aaa96c1a-20d1-43bf-819/eazybank --format="value(package)"

5IAM binding so GKE nodes can pull persists

Critical Without this, pods stay in ErrImagePull with 403 Forbidden. The node pool's default oauth scopes (devstorage.read_only) do work for Artifact Registry — only the IAM is missing. 
gcloud artifacts repositories add-iam-policy-binding eazybank `
  --location=us-central1 `
  --member=serviceAccount:594159792471-compute@developer.gserviceaccount.com `
  --role=roles/artifactregistry.reader

Idempotent. If the binding already exists (persisted from a previous session), it does not error.

6Create the GKE cluster

Size With 3 e2-medium nodes (~4.5 usable vCPU) the full stack does not fit — Keycloak stays Pending. Start with 4 nodes. 
gcloud container clusters create cluster-1 `
  --zone us-central1-a --num-nodes 4 --machine-type e2-medium `
  --disk-size 32 --release-channel regular

Takes ~3-5 min. When it's done, wire kubectl:

gcloud container clusters get-credentials cluster-1 --zone us-central1-a
kubectl get nodes    # should show 4 Ready

7Deploy the base infra

The first three are standalone manifests, independent of each other:

kubectl apply -f redis.yaml
kubectl apply -f h2-server.yaml
kubectl apply -f discovery-server.yaml

Kafka and Keycloak via Helm (each with --wait):

helm upgrade --install kafka helm/kafka --wait --timeout 5m
helm upgrade --install keycloak helm/keycloak --wait --timeout 5m

8Deploy the 6 microservices

The gke-values.yaml overlay points at the Artifact Registry paths and lowers replicas to 1:

helm upgrade --install dev-env helm/environments/dev-env `
  -f helm/environments/dev-env/gke-values.yaml --timeout 8m

Check pods and the gateway LoadBalancer:

kubectl get pods
kubectl get svc gatewayserver keycloak

The gateway and keycloak EXTERNAL-IP takes 1-2 min to be assigned.

9Validate end-to-end (Bruno)

Keycloak runs H2 in memory — every recreation loses clients and roles:

.\create-keycloak-client.ps1 -ClientId eazybank-callcenter-cc -Roles ACCOUNTS,CARDS,LOANS
# copy the `secret` it prints

In Bruno (collection bruno-collection/):

  1. Env Remote-GKE → update gatewayUrl and keycloakUrl with the current EXTERNAL-IPs.
  2. Paste the clientSecret.
  3. Run Auth/Get Token → Accounts/Create → Accounts/Fetch → Accounts/Delete. Should return 200/201.
JWT issuer The gateway only has jwk-set-uri (no issuer-uri) → it does not validate iss. Logging in against Keycloak's public IP works even though the JWKs are read internally.

10Kill switch when done

ALWAYS when done. Two levels depending on how long until you come back.

Level A — pause (coming back in days/weeks)

Just deletes the cluster and orphan PVC disks. Keeps the AR repo with the images → ~$0.06/month → on recreation you skip §3 and §4.

gcloud container clusters delete cluster-1 --zone us-central1-a --quiet

# PVC disks (Kafka/Keycloak) are NOT automatically deleted:
gcloud compute disks list --format="value(name,zone)"
# And for each one:
gcloud compute disks delete <PVC-NAME> --zone=us-central1-a --quiet

Level B — $0 cost (coming back in months, or maybe never)

On top of Level A, also delete the AR repo (with all the images inside):

gcloud artifacts repositories delete eazybank --location=us-central1 --quiet
Persists Level B leaves enabled APIs (free) and the orphan IAM binding — harmless. The next recreation has to run §3, §4 and §5 again.

Verify $0 cost

gcloud container clusters list
gcloud compute disks list
gcloud compute addresses list
gcloud compute forwarding-rules list
gcloud artifacts repositories list --location=us-central1

Everything should come back empty. If anything shows up — delete it.

11Quick troubleshooting

SymptomCauseFix
Pods in ErrImagePull; describe shows 403 fetch oauth token Missing IAM binding on the compute SA Apply §5. The binding is idempotent
kubectl: gke-gcloud-auth-plugin not found Plugin not on PATH See §0 (extend $env:PATH) or new PowerShell
Keycloak stuck in Pending Cluster with 3 e2-medium nodes — doesn't fit Recreate with --num-nodes 4
Gateway EXTERNAL-IP: <pending> for more than 5 min GCP LB is slow or quota exhausted Wait. Quota: gcloud compute forwarding-rules list
Bruno 401 on Accounts Token expired (~1 min) or Keycloak restarted (H2 in memory) Re-Auth/Get Token. If it persists: re-run create-keycloak-client.ps1
OpenTelemetry traces failing to tempo No observability deployed Ignore — harmless noise
