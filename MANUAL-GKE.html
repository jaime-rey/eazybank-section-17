Doc autocontenido para volver a montar el cluster en meses sin recordar nada. Asume que se parte de un proyecto GCP vacío (sin repo, sin imágenes, sin nada) y termina con un cluster GKE corriendo los 6 microservicios y validado desde fuera con Bruno.

Al día El repo de EazyBank Section 17 debe estar clonado localmente en C:\Users\User\spring boot\section_17. Todos los comandos se ejecutan desde ahí en PowerShell.
Coste actual Todo borrado el 2026-08-07. Estado $0/mes. Ver §12 para el desglose al recrear.

0Prereqs de la máquina

  • Google Cloud SDK (gcloud + gke-gcloud-auth-plugin). Windows: instalador oficial.
  • kubectl — gcloud components install kubectl o el que viene con Docker Desktop.
  • helm v3+.
  • Docker Desktop — necesario para el build+push de imágenes en §4.
  • JDK 17+ — para el build de Jib.
Warning Si kubectl se queja de gke-gcloud-auth-plugin not found, el plugin no está en el PATH. Añádelo en la sesión con: 
$env:PATH += ";C:\Users\User\AppData\Local\Google\Cloud SDK\google-cloud-sdk\bin"
o abre una PowerShell nueva.

1Login en GCP y configurar el proyecto

gcloud auth login
gcloud config set project project-aaa96c1a-20d1-43bf-819
gcloud config set compute/region us-central1
gcloud config set compute/zone us-central1-a

El gcloud auth login abre el navegador para OAuth. Una sola vez por máquina/cuenta.

2Habilitar APIs persiste

Habilita tres APIs. Si ya están enabled, este comando es idempotente y no cobra nada.

gcloud services enable container.googleapis.com artifactregistry.googleapis.com compute.googleapis.com

Comprobar:

gcloud services list --enabled --filter="name:(container.googleapis.com OR artifactregistry.googleapis.com OR compute.googleapis.com)" --format="value(config.name)"

3Crear el repo de Artifact Registry borrado 2026-08-07

gcloud artifacts repositories create eazybank `
  --repository-format=docker --location=us-central1 `
  --description="EazyBank microservices Docker images"

El repo cuesta ~$0.06/mes por las imágenes que contendrá (~630 MB). Ver §12.

4Build local + push al Artifact Registry

Configura Docker para autenticar contra AR (una sola vez por máquina):

gcloud auth configure-docker us-central1-docker.pkg.dev

Build de las 6 imágenes con Jib (produce tags eazybytes/<svc>:s17):

cd "C:\Users\User\spring boot\section_17"
.\build-images-s17.ps1

Retag y push:

$svcs = @("configserver","accounts","cards","loans","gatewayserver","message")
foreach ($s in $svcs) {
    $dst = "us-central1-docker.pkg.dev/project-aaa96c1a-20d1-43bf-819/eazybank/${s}:s17"
    docker tag "eazybytes/${s}:s17" $dst
    docker push $dst
}

Comprobar que están las 6:

gcloud artifacts docker images list us-central1-docker.pkg.dev/project-aaa96c1a-20d1-43bf-819/eazybank --format="value(package)"

5IAM binding para que los nodos GKE puedan pull persiste

Crítico Sin esto, los pods se quedan en ErrImagePull con 403 Forbidden. Los oauth scopes default del node pool (devstorage.read_only) sí sirven para Artifact Registry — solo falta el IAM. 
gcloud artifacts repositories add-iam-policy-binding eazybank `
  --location=us-central1 `
  --member=serviceAccount:594159792471-compute@developer.gserviceaccount.com `
  --role=roles/artifactregistry.reader

Es idempotente. Si el binding ya existe (persistió de una sesión anterior), no da error.

6Crear el cluster GKE

Tamaño Con 3 nodos e2-medium (~4.5 vCPU útiles) no cabe el stack completo — Keycloak se queda Pending. Arrancar con 4 nodos. 
gcloud container clusters create cluster-1 `
  --zone us-central1-a --num-nodes 4 --machine-type e2-medium `
  --disk-size 32 --release-channel regular

Tarda ~3-5 min. Al terminar, conectar kubectl:

gcloud container clusters get-credentials cluster-1 --zone us-central1-a
kubectl get nodes    # deben salir 4 Ready

7Deploy de la infra base

Los tres primeros son manifiestos sueltos, independientes entre sí:

kubectl apply -f redis.yaml
kubectl apply -f h2-server.yaml
kubectl apply -f discovery-server.yaml

Kafka y Keycloak vía Helm (cada uno --wait):

helm upgrade --install kafka helm/kafka --wait --timeout 5m
helm upgrade --install keycloak helm/keycloak --wait --timeout 5m

8Deploy de los 6 microservicios

El overlay gke-values.yaml apunta a las rutas de Artifact Registry y baja replicas a 1:

helm upgrade --install dev-env helm/environments/dev-env `
  -f helm/environments/dev-env/gke-values.yaml --timeout 8m

Comprobar pods y el LoadBalancer del gateway:

kubectl get pods
kubectl get svc gatewayserver keycloak

La EXTERNAL-IP del gateway y de keycloak tarda 1-2 min en asignarse.

9Validar end-to-end (Bruno)

Keycloak corre H2 en memoria — cada recreación pierde clientes y roles:

.\create-keycloak-client.ps1 -ClientId eazybank-callcenter-cc -Roles ACCOUNTS,CARDS,LOANS
# copiar el `secret` que imprime

En Bruno (colección bruno-collection/):

  1. Env Remote-GKE → actualizar gatewayUrl y keycloakUrl con las EXTERNAL-IP actuales.
  2. Pegar el clientSecret.
  3. Correr Auth/Get Token → Accounts/Create → Accounts/Fetch → Accounts/Delete. Deben devolver 200/201.
JWT issuer El gateway solo tiene jwk-set-uri (no issuer-uri) → no valida el iss. Vale hacer login contra la IP pública de Keycloak aunque los JWK los lea internamente.

10Kill switch al terminar

SIEMPRE al terminar. Dos niveles según cuánto vayas a tardar en volver.

Nivel A — pausa (vuelves en días/semanas)

Solo borra el cluster y los disks huérfanos de PVCs. Se mantiene el repo AR con las imágenes → coste ~$0.06/mes → al recrear te saltas §3 y §4.

gcloud container clusters delete cluster-1 --zone us-central1-a --quiet

# Los disks de PVCs (Kafka/Keycloak) NO se borran automaticamente:
gcloud compute disks list --format="value(name,zone)"
# Y para cada uno:
gcloud compute disks delete <PVC-NAME> --zone=us-central1-a --quiet

Nivel B — coste $0 (vuelves en meses o quizá nunca)

Además del Nivel A, borra también el repo AR (con todas las imágenes dentro):

gcloud artifacts repositories delete eazybank --location=us-central1 --quiet
Persiste Nivel B deja APIs habilitadas (gratis) y el IAM binding huérfano — inofensivo. La próxima recreación tiene que ejecutar §3, §4 y §5 de nuevo.

Verificar coste $0

gcloud container clusters list
gcloud compute disks list
gcloud compute addresses list
gcloud compute forwarding-rules list
gcloud artifacts repositories list --location=us-central1

Todo debe salir vacío. Si aparece algo — bórralo.

11Troubleshooting rápido

SíntomaCausaFix
Pods en ErrImagePull; describe muestra 403 fetch oauth token Falta IAM binding en la compute SA Aplicar §5. El binding es idempotente
kubectl: gke-gcloud-auth-plugin not found Plugin no en PATH Ver §0 (extend $env:PATH) o PowerShell nueva
Keycloak en Pending indefinidamente Cluster con 3 nodos e2-medium — no cabe Recrear con --num-nodes 4
Gateway EXTERNAL-IP: <pending> más de 5 min LB de GCP tardando o cuota agotada Esperar. Cuota: gcloud compute forwarding-rules list
Bruno 401 en Accounts Token expiró (~1 min) o Keycloak reinició (H2 en memoria) Re-Auth/Get Token. Si sigue: re-ejecutar create-keycloak-client.ps1
Trazas de OpenTelemetry fallando a tempo No hay observabilidad desplegada Ignorar — ruido inofensivo
